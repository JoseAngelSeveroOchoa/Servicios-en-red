    Unidad 1: Servicio DHCP

    1. Introducción

    Para que un dispositivo pueda operar e identificarse de forma unívoca en una red informática, requiere disponer de una dirección IP única. Cuando el volumen de equipos (ordenadores, servidores, impresoras) crece, la asignación e introducción manual de direcciones resulta tediosa, repetitiva y compleja de administrar.

    Para solventar esta problemática se utiliza el servicio DHCP (Dynamic Host Configuration Protocol), el cual automatiza la entrega dinámica y centralizada de direcciones IP, máscaras de subred, puertas de enlace (gateways) y otros parámetros de red.

    2. Ventajas del Uso del Servicio

    • Centralización de la administración: Toda la topología de direccionamiento se gestiona desde el archivo de configuración del servidor.
    • Prevención de errores y conflictos: Evita la asignación accidental de direcciones IP duplicadas o configuraciones erróneas en los clientes.
    • Ahorro de tiempo operativo: Prescinde de la necesidad de intervenir localmente en la configuración de red de cada equipo cliente.

    3. Funcionamiento y Tipos de Mensajes

    El servicio opera bajo una arquitectura Cliente-Servidor. Un cliente configurado para obtener direccionamiento automático iniciará un intercambio de paquetes para solicitar parámetros al servidor.

    Los parámetros habitualmente asignados son:

    • Dirección IP y Máscara de subred
    • Servidores DNS
    • Puerta de enlace (Gateway)

    Secuencia de Negociación (Proceso DORA)

    Flujo de comunicación entre Cliente y Servidor

    1. DHCP DISCOVERY (Broadcast)
      El cliente no conoce la red y envía una solicitud por difusión a todos los equipos.

    2. DHCP OFFER (Unicast)
      El servidor revisa sus IP disponibles y le ofrece una al cliente con los parámetros de red.

    3. DHCP REQUEST (Broadcast)
      El cliente acepta la oferta y lo notifica a toda la red para que otros servidores lo sepan.

    4. DHCP ACK / NACK (Unicast)
      El servidor confirma la concesión (ACK) y registra la asignación, o la rechaza (NACK) si ya no es válida.

    Tipos de Mensajes DHCP

    • DHCP DISCOVERY: Mensaje de difusión (broadcast) que envía el cliente al conectarse a la red para localizar qué servidores DHCP hay disponibles.
    • DHCP OFFER: Respuesta enviada por el servidor con la propuesta de dirección IP y el resto de parámetros de configuración de red.
    • DHCP REQUEST: Mensaje del cliente aceptando la oferta recibida. Se envía en broadcast para que los demás servidores DHCP sepan que esa IP ya ha sido asignada.
    • DHCP ACK / NACK:
      • ACK: El servidor confirma la configuración, la anota en sus registros y autoriza al cliente a usar la IP.
      • NACK: El servidor deniega la asignación si la IP no es válida para esa subred o ya está en uso.
    • DHCP RELEASE: Mensaje opcional que transmite el cliente para liberar la IP asignada y finalizar el contrato de concesión antes de tiempo.

    4. Archivo de Configuración (dhcpd.conf)

    En sistemas Linux, el archivo de configuración principal se ubica en el directorio /etc/dhcp/dhcpd.conf.

    El archivo se compone de parámetros (definen directivas globales o locales) y declaraciones (delimitan ámbitos como subredes, grupos o equipos):

    ```text # Parámetros globales default-lease-time 86400; max-lease-time 172800;

    Declaración de Subred

    subnet 192.168.1.0 netmask 255.255.255.0 { range 192.168.1.11 192.168.1.29; option routers 192.168.1.1; option domain-name-servers 192.168.1.1, 8.8.8.8; }
